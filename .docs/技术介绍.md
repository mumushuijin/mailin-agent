> 版本：0.1.0  
> 最后更新：2026-09-14  
> 范围：基于当前仓库源码梳理，覆盖 `backend/` 与 `frontend/`

---

## 1. 项目定位

麦林 Mailin 是一个本地优先的个人 AI Agent 应用。它把“面向本机项目目录的对话式协作”作为核心场景：用户先绑定一个项目文件夹，再在同一会话中让 Agent 读写文件、运行命令、整理上下文、沉淀记忆、调用 MCP 或其他内置工具。

项目采用前后端分离架构：

| 层级 | 主要职责 |
|------|----------|
| 前端 `frontend/` | Vue 单页应用与 Electron 桌面壳，负责聊天 UI、项目/会话导航、流式事件展示、工具审批、设置、记忆和技能管理 |
| 后端 `backend/` | FastAPI 服务，负责会话管理、LangGraph Agent 推理、工具执行、上下文压缩、记忆沉淀、MCP 生命周期和本地持久化 |
| 本地工作区 `backend/workspace/` | 运行时数据目录，保存配置、bootstraps、每日记忆、会话索引、checkpoint 和历史投影 |
| 用户项目目录 | 每个会话绑定的真实项目文件夹，文件和 Shell 工具默认在这里运行，项目规则种子为 `AGENTS.md` |

核心取舍是“本地可控优先，而不是多人云服务”。因此当前项目没有认证、多租户和云同步设计；它更像个人开发工作台，而不是 SaaS。

## 2. 一句话架构

```text
Vue/Electron 前端
  -> REST 管理接口 + WebSocket 主聊天通道 + SSE 降级通道
  -> FastAPI 服务层
  -> LangGraph ReAct 图
  -> 上下文引擎 + 工具注册中心 + 本地工作区
  -> SQLite checkpoint / JSON 索引 / 项目 sidecar 文件
```

更具体的数据流：

```text
用户输入
  -> ChatView 生成本地 UI 消息与 run_id
  -> ChatWebSocket 发送 chat.send
  -> WsChatService 创建异步 run
  -> ChatService 准备记忆、图、初始状态
  -> LangGraph agent 节点组装上下文并调用 LLM
  -> 如有 tool_calls，tools 节点执行工具，必要时 interrupt 等待审批
  -> streaming mapper 将 LangGraph 事件翻译成 AgentEvent
  -> 前端按 token / tool / stage / usage / interrupt 更新界面
  -> 完成后刷新历史投影、自动标题、可能触发记忆整理
```

## 5. 后端架构速读

后端入口是 `backend/app/main.py`。FastAPI `lifespan` 中按顺序完成：

1. 读取 `.env` 与 settings。
2. 初始化日志、运行工作区和 LangSmith 遥测。
3. 注册默认韧性策略和 Agent hooks。
4. 打开 SQLite checkpointer。
5. 清理工具缓存并预编译 LangGraph 图。
6. 启动后台维护调度器。

关闭时会停止维护任务、关闭 MCP、清工具缓存、清图缓存、关闭 checkpoint 连接。

后端 API 统一挂在 `/api` 前缀下：

| 模块 | 路径 | 说明 |
|------|------|------|
| 健康检查 | `GET /health` | 返回服务是否可用、是否配置 LLM |
| Chat | `/api/chat` | 同步排障入口和 SSE 流式降级 |
| WebSocket | `/api/ws/chat` | 主聊天通道、会话订阅、取消、审批、问用户 |
| Session | `/api/session` | 会话 CRUD、分页历史、工具结果读取 |
| Config | `/api/config` | CONFIG 与 bootstrap 配置读写、初始化 |
| Memory | `/api/memory` | 每日记忆列表和详情 |
| Skills | `/api/skills` | 全局/项目 skill 列表、刷新、匹配、详情、启停 |

详见：[后端技术详解](./后端技术详解.md)。

## 6. Agent 运行模型

Agent 使用 LangGraph 的 `StateGraph(AgentState)` 实现 ReAct 循环：

```text
START -> agent -> tools? -> tools -> agent -> ... -> END
```

关键点：

| 设计点 | 当前实现 |
|--------|----------|
| 状态账本 | `messages` 使用 LangGraph `add_messages` 累加，作为完整会话账本 |
| 运行窗口 | `working_messages` 每轮由上下文引擎临时组装，不作为用户可见历史 |
| 线程映射 | `session_id` 映射为 LangGraph `thread_id` |
| 迭代预算 | `max_steps` 默认 24，达到预算后要求模型做收束总结 |
| 工具执行 | 通过 `ToolCard` 注册，热工具直接 bind，冷工具经 `tool_search -> tool_describe -> tool_call` |
| 人工介入 | 高风险工具或 `ask_user` 通过 LangGraph `interrupt` 暂停，再由 WebSocket 恢复 |
| 错误恢复 | LLM/工具/上下文步骤套统一 resilience policy，失败时返回可展示错误 |

这套设计的好处是：推理、工具、审批、流式事件都在同一个图状态里闭环，checkpoint 可以保留中断点，前端不需要理解 LangGraph 内部细节。

## 7. 上下文与长会话

上下文引擎位于 `backend/app/context/`。它解决的问题不是“把所有历史都塞给模型”，而是从完整账本派生一个可控的工作窗口：

```text
System bootstrap
  + 参考信息块：skills catalog / memory hints / tools disclosure / context summary
  + 中间历史：必要时压缩为摘要
  + 尾部窗口：最近交互尽量完整保留
```

默认上下文预算来自 `backend/workspace_defaults/CONFIG.json`：

| 区块 | 默认比例 |
|------|----------|
| bootstrap | 18% |
| skills | 4% |
| summary | 12% |
| recent_turns | 28% |
| tool_results | 25% |
| current_message | 5% |
| reserved | 8% |

压缩策略分层：

| 层 | 目的 |
|----|------|
| Layer A | 尾部超大工具结果摘要化，并把全文延后落盘 |
| Layer B | 尾部窗口外的旧工具结果压成一行，降低工具输出污染 |
| Middle Summary | 预算压力大时用 LLM 汇总中间历史 |
| Reject | 压缩次数耗尽或仍超限时拒绝继续 |
| Emergency | 捕获上下文超长类错误后紧急压缩重试 |

重要边界：完整账本不被压缩；压缩只影响给模型看的 `working_messages` 和持久化的 `context_summary`。这使历史可追溯，同时控制每轮请求成本。

## 8. 工具系统

工具不是散落函数，而是统一抽象成 `ToolCard`：

```text
ToolPackage manifest
  -> build_cards()
  -> ToolCard: name / summary / description / parameters / risk / sandbox / concurrency / display
  -> LangChain StructuredTool
  -> LangGraph tools 节点执行
```

内置工具包：

| 包 | 工具 | 说明 |
|----|------|------|
| filesystem | `read_file`、`write_file`、`replace_in_file`、`list_directory`、`search_files`、`glob_search`、`mkdir`、`move_file`、`delete_file` | 只在绑定项目工作区内操作；写/移/删需要确认 |
| shell | `run_shell`、`process` | 在项目目录执行命令，支持后台进程、取消和会话级进程表 |
| session | `todo`、`ask_user` | 会话内待办和向用户发问 |
| skills | `skill_list`、`skill_match`、`skill_read` | 渐进式加载全局与项目级 skill |
| memory | `memory_list`、`memory_get`、`memory_grep`、`memory_add`、`memory_consolidate` | 每日记忆和长期记忆 |
| calculator | `python_calculator` | AST 白名单数学计算 |
| datetime | `get_current_time` | 时区感知当前时间 |
| web | `web_search` | Tavily 优先，未配置时 DuckDuckGo；默认关闭 |
| mcp | `mcp_status` 和远程 MCP 工具 | 根据 `mcp_servers` 动态暴露 |

当前默认启用了渐进式工具披露：常用热工具直接给模型，其他工具进入 BM25 catalog。这样能降低工具 schema 对上下文的占用，也让大量 MCP 工具不会一次性压垮 prompt。

## 9. 会话、工作区与持久化

项目里有两个“工作区”概念，必须区分：

| 概念 | 路径 | 用途 |
|------|------|------|
| Agent 自有空间 | `backend/workspace/` | 存配置、bootstraps、每日记忆、会话 index、checkpoint、历史投影 |
| 会话绑定项目 | 用户选择的本机目录 | 文件系统和 Shell 工具实际操作的目录，也会播种 `AGENTS.md` |

为什么聊天前必须绑定项目目录：

1. 防止工具默认落到 Agent 自有空间，误改配置或记忆。
2. 让每个会话有清晰的工作对象。
3. 让工具结果 sidecar 能保存到项目下 `.mailin/tool_results/{session_id}/`。

持久化分三层：

| 数据 | 存储 |
|------|------|
| 会话索引 | `workspace/sessions/index.json` |
| 完整图状态 | `workspace/sessions/checkpoints.sqlite` |
| 前端分页历史投影 | `workspace/sessions/history_projection/{session_id}.json` |

历史投影只服务前端快速分页，不替代 checkpoint。checkpoint 才是 LangGraph 的状态来源。

## 10. 前端架构速读

前端入口是 `frontend/src/main.ts`、`frontend/src/App.vue`。App 外层由 Ant Design Vue `ConfigProvider` 注入主题，布局由自定义标题栏、项目侧边栏、主内容区和维护通知组成。

路由：

| 路由 | 页面 |
|------|------|
| `/` | ChatView |
| `/settings/config` | 配置管理 |
| `/settings/memory` | 每日记忆浏览 |
| `/settings/skills` | 技能管理 |
| `/sessions`、`/config`、`/memory`、`/skills` | 兼容旧路径，重定向 |

ChatView 的主要能力：

| 能力 | 实现 |
|------|------|
| 项目绑定 | 输入绝对路径或 Electron 目录选择器，调用 session create/rebind |
| 流式聊天 | 优先 WebSocket，失败降级 SSE |
| UI 事件批处理 | `createChatStreamEventBatcher` 把高频 token/usage/stage 合并到 animation frame |
| 长历史 | 初始加载最近 30 条，向上滚动分页加载更早历史 |
| 工具展示 | 按 tool_start/tool_finish 组织为可折叠工具卡，隐藏桥接工具 |
| 人工审批 | `ToolApprovalModal` 和 `AskUserModal` 回传 allow/deny 或用户回答 |
| 用量显示 | `ContextUsageRing` 展示上下文、API、缓存命中等统计 |
| 取消 | WebSocket `chat.cancel`，后端取消任务并修复未闭合 tool_calls |

## 11. 运行方式

### 后端

```bash
cd backend
uv sync
cp .env.example .env
uv run mailin serve
```

`.env` 至少配置一个兼容 OpenAI 的密钥：

```text
OPENAI_API_KEY=...
# 或
DASHSCOPE_API_KEY=...
```

MCP 可选：

```bash
uv sync --extra mcp
```

### 前端 Web

```bash
cd frontend
npm install
npm run dev:web
```

Vite 默认端口 `5173`，代理 `/api` 到 `http://localhost:8000`。

### Electron

```bash
cd frontend
npm run dev
npm run electron:build
```

Electron 开发模式加载 `http://localhost:5173`；生产模式加载 `dist/index.html`，路由使用 Hash 模式，构建 base 为 `./`。

## 12. 安全边界

| 风险 | 处理 |
|------|------|
| 误改 Agent 自有空间 | 项目绑定校验禁止把 `backend/workspace/` 或 `workspace_defaults/` 作为项目目录 |
| 文件越界 | 文件工具使用 workspace-only 策略和路径归一化 |
| 高风险文件操作 | 写入、替换、移动、删除标记为 moderate/dangerous，并要求确认 |
| Shell 风险 | `safety_mode`、auto approve 白名单、危险命令 interrupt、会话级进程取消 |
| XSS | Markdown 渲染使用 DOMPurify |
| Electron 权限 | `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、preload 只暴露窗口/目录相关 API |
| 密钥 | `.env` 管理，不进入前端构建产物 |
| API 暴露 | 当前定位本地单机，无鉴权；不建议直接暴露到公网 |

| 维度 | 当前实现 |
|------|----------|

## 14. 当前限制

| 限制 | 影响 |
|------|------|
| 无认证和权限系统 | 适合本地单人，不适合开放网络环境 |
| 会话索引是 JSON 文件 | 单机足够；并发写入和跨设备同步不是当前目标 |
| SQLite checkpoint 单实例 | 本地可靠，横向扩展不是当前目标 |
| 前端没有复杂状态库 | 当前状态规模可控；若页面继续增多，可评估 Pinia |
| WebSocket 审批是主路径 | SSE 可降级流式文本，但需要 interrupt 的流程必须使用 WS |
| MCP 默认懒连接 | 启动快，但首次使用外部 MCP 可能有连接延迟 |

## 15. 被拷打时的高频问题

### 为什么不用后端数据库，而是 JSON + SQLite？

项目定位是本地单人 Agent 工作台。LangGraph 的 checkpoint 需要保存图状态，因此用 SQLite；会话列表和历史投影是轻量索引/展示缓存，JSON 更直观、迁移成本低。真正的会话状态不依赖前端投影。

### 为什么必须先绑定项目目录？

因为 Agent 会读写文件和执行 Shell。绑定项目目录后，工具有明确 cwd 和沙箱边界，避免默认写进 Agent 自有空间；同时可以把项目规则 `AGENTS.md` 和工具结果 sidecar 放在项目边上。

### 长对话怎么处理上下文爆炸？

完整账本持久化，但每轮只从账本派生工作窗口。上下文引擎把 bootstrap、skills、记忆提示、摘要、最近对话、工具结果分预算计量，超过阈值后先压工具结果，再压旧工具，再摘要中间历史，最终仍不行才拒绝。

### 工具很多时怎么避免 prompt 里塞满 schema？

用渐进式工具披露。热工具直接 bind 给模型，冷工具进入 BM25 catalog。模型先 `tool_search` 检索，再 `tool_describe` 读取 schema，最后 `tool_call` 代理执行。MCP 工具也可走这条路径。

### 人工审批如何贯通前后端？

后端 tools 节点遇到高风险工具时调用 LangGraph `interrupt` 暂停，WebSocket 服务把 interrupt 转成前端事件，用户在 Modal 中 allow/deny 后，前端发 `approve`，后端用 `Command(resume=...)` 继续图执行。

### 为什么 WebSocket 是主路径，还保留 SSE？

WebSocket 能双向通信，适合流式、取消、审批、后台推送。SSE 只适合单向流式，所以保留为降级路径；涉及审批或问用户时，后端会提示必须走 WebSocket。

### 历史为什么要 projection？

LangGraph checkpoint 是状态来源，但直接从 checkpoint 转展示历史可能慢，尤其工具结果很大。history projection 把前端展示格式缓存成 JSON，支持最近页优先和分页加载；缺失时可由 checkpoint 重建。

### 取消生成后怎么避免状态坏掉？

WebSocket 服务取消 run 后会调用 `repair_cancelled_checkpoint`，把未完成的 tool_calls 修成取消结果，避免下一轮出现 orphan tool call 破坏消息账本。

### Skills 和 Tools 有什么区别？

Tool 是 Agent 可以调用的操作能力；Skill 是给 Agent 的任务方法说明。Skill 默认只注入轻量目录，完整 `SKILL.md` 通过 `skill_read` 按需加载，项目级 skill 可以覆盖同名全局 skill。
